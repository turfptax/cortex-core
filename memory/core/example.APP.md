## What this is

Cortex is a **personal AI memory system**. Its declared mission, in the user's own words:

> "To save and process all my digital data for future serving to new AIs for context."

It runs across multiple hosts (a Raspberry Pi or Orange Pi, a desktop Hub, a wearable companion device, an MCP server). The corpus accumulates over time. The interpretive layers (themes, patterns, journal) make it queryable. The vault makes it human-readable. The MCP tools make it AI-readable.

---

## The three functions

These are the answer to "what is Cortex for?" Every feature should be classifiable into one of these three:

### F1 — Serve digital data to future AIs for context (PRIMARY)
**Audience**: External AIs working with the user in tools that don't have Cortex wired in directly.
**What it requires**: a layered corpus (abstractions / gists / raw), a reader surface (vault + MCP), sensitivity gating, a refinement loop.
**Success criteria**: an external AI asking "what's the user been working on lately?" gets substantive context in 1-2 calls.

### F2 — User's personal data-org software (SECONDARY)
**Audience**: The user themselves.
**What it requires**: a pleasant Hub UI, quick-capture surfaces (voice journal, notes, file uploads), operational visibility (budget, freshness, status), data organization tools (project classification, sensitivity tagging).
**Success criteria**: the user uses Cortex daily without resentment.

### F3 — R&D testbed for AI maturation (TERTIARY)
**Audience**: The user + future AI researchers.
**What it requires**: experimental infrastructure (sibling dispatch, B/C agents, dialectic, voice mode, training pipelines) + honest outcome tracking.
**Success criteria**: failures get surfaced as drift/pattern; patterns from R&D feed back into how F1+F2 evolve.

## The three layers (F1 implementation)

```
ABSTRACTIONS  ←  pulled first by external AIs
     ↓ link
   GISTS      ←  drilled when abstraction insufficient
     ↓ link
   RAW DATA   ←  drilled rarely; sensitivity redactions on pull
```

- **Abstractions** = themes, patterns, drift, projects, open questions, people, narratives. Cheap, indexed, summary-shaped.
- **Gists** = per-session summaries. Each links to its raw source. Gist PROMPTS are first-class artifacts that evolve.
- **Raw** = imported_sessions + .jsonl files. Source of truth. Sensitivity tier-gated on pull.

**Pull mechanic**: top-down by default. Drill on demand. Every pull is an event that may trigger refinement of the layers it touched.

## Known limitations (be honest)

External AIs reading this should know what doesn't work yet.

- **MCP only reads `notes` table currently.** The interpretive layer (gists, themes, narratives, journal, patterns, drift) is unreachable via MCP. Fix in progress: substring tool + vault generator.
- **3 tables are fully sealed** (patterns, drift_observations, future_overseer_notes) — overseer writes to them, nothing reads from them outside the Pi's internal loop.
- **Vault doesn't exist yet** as of [DATE]. Sibling Task #N is in flight to design it.
- **Some loop steps produce artifacts no one reads** (insight scan candidates, distill corrections). Paused per directive.
