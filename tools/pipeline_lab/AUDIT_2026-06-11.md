# Session classifier audit, 2026-06-11

Pre-rollout review of the Stage 0.5 nature classifier over the 36-session
study set, requested by Tory before committing to the full dataset. Four
independent reviewers read the RAW human-typed turns of every session and
judged the assigned category cold.

## Verdicts on the original classifier

33 CORRECT, 3 QUESTIONABLE, 0 WRONG.

The questionables:
1. `a0ff4654` (Lemon-LM-Squeeze): a human-seeded /loop session. 160 of 172
   "human" turns were loop machinery re-injecting the same prompt, which
   dragged it to automation-checkin. The audited truth: a human typed a real
   project spec, a loop drove the build, the human steered ~9 times.
   Closest honest label: human-build.
2. `d022e898` (the three-functions articulation session): correctly
   human-build structurally, but it contains the foundational F1/F2/F3
   design dialogue. A flat 0.8 weight undersells its memory value.
3. `29c61b8d` (the phone-app pivot session): same shape; the tool work
   served a direction-setting decision that later became a LOCKED seed.

## Systemic findings (convergent across all four reviewers)

1. Harness echoes counted as human turns: scheduled-task preambles,
   task-notifications, system-reminders, /loop command machinery, and
   continuation banners all arrive as user-role messages.
2. Confidence was diluted on the deterministic case: a literal
   `<scheduled-task>` opener with "the user is not present" scored
   0.52-0.70 when it deserves ~0.98.
3. Loop-shaped repetition (the same prompt re-injected many times) had no
   signal.
4. Mid-session harness traffic must not flip a human session: the decisive
   question is WHO OPENED the session and how many genuinely distinct
   human turns followed.

## Fixes applied (same day, re-validated)

- User-role turns are now split three ways: human-typed, harness-injected,
  tool-result echoes. Harness prefixes: `<scheduled-task`,
  `<task-notification`, `<system-reminder`, `<command-name`,
  `<local-command-caveat`, `[SYSTEM NOTIFICATION`, continuation banners.
- New signals: `genuine_human_messages` (human turns minus the dominant
  repeated template), `harness_messages`, `max_repeated_human_turn`,
  `opened_by_scheduler` (replaces marker-anywhere detection).
- All category rules re-keyed to `genuine_human_messages`; scheduler
  evidence only dominates when genuine human follow-up is minimal.
- Deterministic confidence override: scheduler-opened with <= 1 human turn
  classifies automation-checkin at 0.98 (method `rules-deterministic`).

Re-validation: 36/36 match the audit ground truth (including the /loop
session resolving to human-build), all 13 check-ins at 0.98, ZERO LLM
escalations needed. The first version of the harness-exclusion fix
over-rotated (marker-anywhere flipped human sessions with mid-session
notifications); the opened-by-scheduler decomposition fixed it.

## Recommendations NOT implemented (Tory's call)

- Decision-salience flag: sessions 2 and 3 above argue for a secondary
  "contains direction-setting decisions" signal on top of the category, so
  foundational dialogue inside build marathons is not flattened to 0.8.
  This is a content signal (cheap LLM pass or keyword heuristic), best
  decided alongside the gist-prompt work after the study.
- Pasted-content fraction: a session where the human only couriers AI
  output between AIs would still classify human-dialogue today. Rare, but
  real (seen in the Grok relay session, where the human did also decide).
- Rollup keying: check-ins could be grouped by their scheduled-task name
  (e.g. `cortex-overseer-checkin-b`), giving rollups a natural key.
- Console hygiene: anything printing raw turns on Windows needs
  PYTHONIOENCODING=utf-8 (cp1252 chokes on corpus content).

## Cost reality for the full dataset

Classification is rules-first: this set needed 0 LLM calls after
hardening. Worst case at ~5-10 percent escalation over ~3,000 sessions is
under $0.30 total. The expensive operation remains GISTING, which is the
existing pipeline's cost, not this stage's.
